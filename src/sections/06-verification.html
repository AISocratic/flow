06Verification loop

Quality as a number, enforced by a loop.

A card can declare a goal percentage. When it does, an independent verification agent scores the finished work 0–100 against the card's intent. Below the bar, the work goes back — same branch, same PR, with the score's critique attached — until it passes or the card's loop limit is spent. Every attempt is logged on the card, so the cost of quality is visible, not hidden.

Two levels of evaluation

Verification is not the only judgment the system makes. Task or PR verification runs before merge and asks whether the implementation satisfies the card. Epic result evaluation runs after all the work is complete — and, where the completion policy requires it, after deployment metrics have arrived — and asks whether the finished body of work achieved its intended result. A card can pass every gate in the first level and still belong to an epic that failed the second.

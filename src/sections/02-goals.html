02Goals, KPIs & planning horizons

The mission, translated into numbers the system can act on.

Humans define the company's goals and KPIs, normally once per quarter. Each goal connects a strategic outcome to one or more measurable indicators — "grow newsletter signups 25%", "p75 LCP under 2s". Agents can recommend goals, surface metric gaps and propose changes, but the final goals and targets stay human-controlled. Each goal also carries guardrail metrics, so the system cannot improve one number by quietly damaging another: a signup-growth goal watches unsubscribe rate, spam complaints, signup quality, acquisition cost and page performance alongside the number it is trying to move.

Below the goals, work is decomposed by agents and the horizons get shorter at every level:

  • Mission — approximately one year.
  • Goals and KPIs — approximately one quarter.
  • Projects and features — open for as long as they remain a valid way of reaching a goal.
  • Epics — bounded bodies of work inside a project.
  • Tasks and bugs — short execution units an agent can claim and finish.
Projects are containers, not weekly plans A planning agent does not create a new project every week. A weekly ritual may still create or reprioritise work, but a project is a persistent strategic container that can hold many successive epics and outlive several goal cycles. As metrics change, agents create new epics, revise planned ones, or recommend closing the project outright.

That traceability is what lets the evaluator ask, months after a change shipped, whether it actually moved the number it was created to move.

04Agents — engineers, operators, QA & judges

The workforce. One isolated workspace each.

Engineer agents build: each gets a fresh git worktree (a full checkout with dependencies linked in), so parallel agents never collide on files. The pipeline is fixed: branch → implement → lint → test → push → open PR → report back. Operator agents run the non-code work — content, emails, triage, scheduled rituals. QA & judge agents monitor the platform — sweeps, verification scoring, anomaly watching — and create new tickets, or alert the user when something's off. Every agent keeps durable state: a memory.md of what it has learned, and a per-run steps.md trail of what it did, so knowledge compounds across runs and any run is auditable.

Running on subscriptions, not credits

The economics are a design constraint, not an afterthought. Mission-critical work runs on the AI subscriptions you already pay for — the Claude Code and Codex seats sitting on your desk — so the bill stays flat as you add agents, and the system gets better every time those harnesses do. Metered API credits are the exception, reserved for models cheap enough to justify on their own merits: Gemma 4, DeepSeek, Kimi 3, GLM 5.2 and friends, on summarization, labelling, dedup and digest work where a wrong answer costs a retry rather than a bad merge. Every card's model + effort policy is what routes it, so the split is a per-card decision you can see and override.

The router is the same model/effort resolution the board already does per card — routing by cost class rather than by capability alone is the only addition.
